# CLAUDE.md

Guidance for Claude Code working in kovirlabs/tagkit. See the Tag Family Ecosystem Spec (section 7) for the plan.

## What this project is

TagKit holds copy-paste page templates and snippets in plain semantic HTML for TagBrush.css and TagAction, the `tagkit build` include CLI (`src/include.mjs`, `bin/tagkit.mjs`, no runtime dependencies), and platform themes (Pandoc here; Jekyll in kovirlabs/tagkit-jekyll).

## Rules

- Plain HTML only: native elements, ARIA attributes, and the classes and `data-` attributes TagBrush.css and TagAction document. No invented classes, no wrapper `<div>`s for layout, no CSS other than variables, no page scripts.
- Every template and snippet must pass TagCheck with no errors or warnings, including `--browser` (contrast in both schemes, phone overflow), work with TagAction, and stay usable with JavaScript off. The tests enforce all of it.
- Realistic example content, not lorem ipsum.
- Edit `snippets/` and `templates/` only. `preview/`, `index.html`, `snippets.json`, the llms.txt catalog, and `ai/` are generated by `npm run build`; never edit them by hand.
- If a snippet needs CSS or JavaScript to look or act right, that's a gap in TagBrush.css or TagAction: raise it there instead of working around it here.
- Each README starts with a one-sentence "Use this when" statement.

## Workflow

- Run `npm test` before every commit (it builds first).
- Small, focused PRs with a CHANGELOG entry.
- When unsure whether something belongs in TagKit, TagBrush, TagAction, or TagCheck, check the spec and ask before building.
